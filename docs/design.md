## Problem Statement

ユーザーが食事の写真をアップロードすると、その食事のEAA（必須アミノ酸9種）摂取量を解析し、日本水産が提示するEAA基準（mg/kg体重/日）に照らして青・黄・赤の信号機スコアを返すWebアプリ。

**EAAスコア（AA比率）の定義**: 各EAAの摂取量が基準値に対して何%充足しているかを示す。最も低い充足率のEAAが全体スコアを決める（制限アミノ酸の概念）。

**ターゲット**: より健康に生きたい人全般 — アスリート、登山家、健康意識の高い一般人。タンパク質の「量」は意識しているが「質」（アミノ酸プロファイル）まで追えていない人たち。

**EAA基準の優先順位**: 日本水産のEAA基準（公開文書で入手できた場合）。入手できない場合はWHO/FAO/UNU 2007基準（Table 26, p.150）を暫定使用。スコアロジックは変わらず、standards.tsの数値差し替えだけで対応できる。

## What Makes This Cool

タンパク質の「量」を追うアプリは飽和状態（Cronometer、MyFitnessPal等）。このアプリはタンパク質の「質」を追う唯一のコンシューマー向けツールになれる。日本水産のEAA基準という具体的なベンチマークを使うことで「EAAバランスが青信号」という明確なフィードバックを返す。

## Constraints

- Next.js 15（App Router）で実装
- MVP優先：精度・デザインの磨き込みは後回し
- 外部API連携のみ。機械学習モデルのトレーニングなし
- 日本語UI
- 画像仕様: JPEG/PNG/WEBP、最大10MB。HEIC不可（MVPでは変換なし）
  - HEIC拒否メッセージ: "iPhoneのHEIC形式はサポートしていません。設定で「最も互換性のある形式」を選択してください。"
- 体重: 60kg固定（MVPでは変更UI不要）。UI上に「体重60kgを基準として計算しています」と表示する
- Vision APIベンダー: **Anthropic Claude claude-sonnet-4-6**（MVPはこれで固定）
- Vercelプラン: **Pro必須**（Hobby tierのデフォルトタイムアウト10秒では不十分）。`maxDuration: 30` を route.ts に設定する

## Premises

1. 写真→アミノ酸プロファイルの変換はVision API + 食品DBルックアップで実現可能（精度は「推定値」でよい）
2. 日本水産のEAA基準を参照スコアとして使う（数値が入手できない場合はWHO/FAO 2007基準で暫定）
3. ターゲットユーザーはすでにタンパク質を意識している人
4. まず動くMVPを作る。磨き込みは後回し
5. Vision APIには日本語食材名を返させる。文科省CSVも日本語食材名でインデックスされているため変換不要

## Approaches Considered

### Approach A: 最小構成（Vision API + 食品DBルックアップ）— CHOSEN
```
写真 → Claude Vision（食材・分量特定） → 文科省食品成分表CSV（アミノ酸取得）→ EAA計算 → 信号機スコア
```
- Effort: 3-5日（USDAの言語壁を文科省CSVで回避するため）
- Risk: Low
- Pros: 学習不要、和食カバレッジが高い、オフラインLookup可能
- Cons: CSVの初期セットアップが必要、データが古い可能性

### Approach B: 確認ステップ付き
- 認識後に「これで合ってますか？」確認フローを追加
- Effort: M（5-7日）
- Approach Aが動いたら追加実装する候補

### Approach C: フル構成（履歴・シェア機能付き）
- バッチアップロード、日別スコア履歴、シェアURL
- Effort: XL（2-4週間）
- 将来の拡張候補

## Recommended Approach

**Approach A**。ただしUSDA（英語専用）ではなく**文科省食品成分表CSV**を使う。これが最大の技術リスク解消になる。

### 技術スタック
- **フレームワーク**: Next.js 15（App Router）
- **Vision API**: Anthropic Claude claude-sonnet-4-6（固定）
- **食品データベース**: 文科省「日本食品標準成分表2020年版」CSV（無料・日本語食材名・アミノ酸データあり）
- **デプロイ**: Vercel

### パイプライン詳細

```
[1] 写真アップロード
    └─ POST /api/analyze
    └─ multipart/form-data、JPEG/PNG/WEBP、最大10MB
    └─ バリデーション: MIMEタイプ・サイズ確認。違反 → 400エラー＋メッセージ

[2] 食材・分量の特定（Claude Vision）
    └─ プロンプト:
       "この食事の写真から見える食材と推定グラム数をJSONで返してください。
        食材名は日本語で、grams は整数で推定してください。
        推定が難しい場合は標準的な1人前の量を使ってください。
        例: [{\"name\": \"鶏むね肉\", \"grams\": 150}, ...]
        食材が認識できない場合は空配列を返してください。"
    └─ 出力: [{name: string, grams: number}]
    └─ 空配列 → エラー「食材を認識できませんでした。明るい場所で撮影し直してください。」
    └─ JSONパース失敗 → エラー「解析結果の形式が不正でした。再試行してください。」
    └─ APIエラー → 「解析に失敗しました。30秒後に再試行してください。」
    └─ タイムアウト: 25秒。超過 → 「解析に時間がかかっています。再試行してください。」
    └─ 解析中は「解析中...」スピナーをUI全面に表示し、操作をブロックする

[3] アミノ酸プロファイル取得（文科省食品成分表CSV）
    └─ 食材名マッチング（優先順位順）:
       1. dictionary.ts 手動マッピングで完全一致（例: "鶏むね肉" → "にわとり　[若鶏肉]　むね　皮なし　生"）
       2. 上記でミスの場合、食品名列に対して部分文字列検索（substring match）
       3. 両方不一致 → 「データなし」として扱い、結果UIに「{食材名}: データなし」と表示
    └─ スコア表示条件: Visionが返した全食材の推定タンパク質合計のうち、CSVでマッチした食材の合計が50%以上の場合のみスコアを表示。
       未満の場合 → スコア非表示。「多くの食材のデータが不足しているため、正確なスコアを算出できませんでした」と表示
    └─ 9種EAA（His, Ile, Leu, Lys, Met+Cys, Phe+Tyr, Thr, Trp, Val）を mg/100g で取得
    └─ grams × (aa_mg / 100) で実量（mg）を計算

[4] 食事全体のEAA合計計算
    └─ 全食材のEAA実量を合算
    └─ 体重60kg × 基準値（mg/kg/日）で1日必要量を算出
    └─ 充足率(%) = 摂取量 / 必要量 × 100

[5] 信号機スコア算出（優先順位順で判定、最初に合致したルールが適用）
    └─ 赤: いずれか1種のEAAの充足率 < 80%（最優先）
    └─ 黄: 赤でなく、いずれか1種のEAAの充足率 80% 以上 100% 未満
    └─ 青: 全EAAの充足率 ≥ 100%
    └─ 閾値（80% / 100%）はMVP暫定値。一般的な食事摂取基準の充足度判定に準拠

[6] 結果表示
    └─ 信号機UI（大きなアイコン）
    └─ 各EAAの充足率バー（9本）
    └─ 不足EAAに対して静的テンプレートで1行コメント（AI呼び出しなし）:
       赤EAAのみ: "{EAA名}が不足しています（充足率{X}%）。"
       黄EAAのみ: "{EAA名}がやや不足しています（充足率{X}%）。"
       青（全充足）: コメントなし
    └─ データなしの食材リスト（存在する場合）
    └─ UI下部に「体重60kgを基準として計算しています」を常時表示
```

### EAA基準値（実装用定数）

日本水産の公開数値が入手できない場合、WHO/FAO/UNU 2007基準（mg/kg/日）を暫定使用：

```typescript
// lib/standards.ts
// Source: WHO/FAO/UNU (2007) "Protein and amino acid requirements in human nutrition"
// Table 26, p.150 — 暫定値。日本水産基準が入手できたら差し替える
export const EAA_STANDARD_MG_PER_KG_DAY = {
  histidine: 10,
  isoleucine: 20,
  leucine: 39,
  lysine: 30,
  methionine_cysteine: 15,    // Met + Cys 合計
  phenylalanine_tyrosine: 25, // Phe + Tyr 合計
  threonine: 15,
  tryptophan: 4,
  valine: 26,
} as const

export const DEFAULT_BODY_WEIGHT_KG = 60
```

### 文科省データの準備手順（初回のみ）
1. https://www.mext.go.jp/a_menu/syokuhinseibun/mext_01110.html から「アミノ酸成分表」をダウンロード
   ※ダウンロードファイルは.xlsx（Excel形式）。CSVではない
2. `scripts/convert-mext.py` でCSVに変換して `data/mext-amino-acids.csv` に出力:
   ```python
   import pandas as pd
   df = pd.read_excel("アミノ酸成分表.xlsx", sheet_name=0, header=3)
   df.to_csv("data/mext-amino-acids.csv", index=False, encoding="utf-8-sig")
   # 変換後、9種EAAカラム（Met+Cys、Phe+Tyr含む）が正しく存在するか検証する:
   # 鶏むね肉（皮なし）の行でisoleucine等が数値であることをassertする
   # METとCYSが別カラムになっている場合は合算カラムを作成する
   ```
3. `lib/food-db.ts` でサーバーサイドの `fs.readFileSync` で読み込む（リクエスト時にディスクから読む）
4. Vercelデプロイ時にCSVが含まれるよう `next.config.ts` に設定:
   ```typescript
   experimental: {
     outputFileTracingIncludes: { '/api/analyze': ['./data/**'] }
   }
   ```

## Open Questions

1. **日本水産のEAA基準の正確な数値**: 公開文書を探す。見つからない場合はWHO/FAO 2007値（上記）で暫定実装する。スコアロジックの構造は同じなので差し替えは1ファイル（standards.ts）だけ。
2. **食材名マッチングの精度**: Claude Visionが返す食材名と文科省CSVの食材名が一致しないケースは手動で対応表（dictionary.ts）を育てる。
3. **HEIC対応**: iPhoneユーザーはHEICで撮影することが多い。MVP後にsharpライブラリで変換する。

## What I noticed about how you think

- 「EAAの質」に目をつけたのは、既存アプリ（カロリー・タンパク質量）で満足できなかった自分なりの問いから来ている。ゼロから考えた切り口で、競合がほぼ存在しない。
- 「日本水産が提示するEAA基準」という具体的なベンチマークを最初から持ってきた。「なんとなく健康的」より「測定可能な基準に照らして青信号」という発想は設計思想として明確で強い。
- 「まずシンプルに動くものを作りたい」とすぐ言えた。完成形を夢想するより動くものを優先するのは、経験的に最速のパス。
- 対象を「アスリートだけ」から「健康に生きたい人全般」に広げたのは正しい。EAA不足は万人の問題で、市場が広がる。
